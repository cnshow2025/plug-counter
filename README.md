# 塞頭計數器

用一張照片數出綠色塞頭的數量。塞頭是塞管子用的，一顆塞頭等於一根管子，所以數塞頭就是數管子。

**線上使用：https://cnshow2025.github.io/plug-counter/**

單一 HTML 檔、純前端。所有運算都在你的瀏覽器裡跑，**照片不會上傳到任何伺服器**，也沒有後端、沒有外部函式庫（只有 Google Fonts 的字型）。

## 怎麼用

1. 開啟網頁，選「從相簿選照片」或「直接用相機拍」（照片也可以直接拖進框裡或貼上）
2. 上方會直接顯示數量，圖上每顆塞頭標一個編號
3. 數錯的話**直接在圖上點**：點空白處補一顆、點圈圈刪一顆，數字即時更新

拍攝建議：讓整捆塞頭佔畫面大一點、背景單純、對焦在塞頭上。解析度不用擔心（見下方實測）。

## 它怎麼算的

1. **找整捆** — 縮到 600 px，用色相 168°±50° 找綠色，並用局部邊緣能量剔除模糊的背景。

   這裡不能直接取「最大的一塊」：每顆塞頭都被自己的透明套環圍住，整捆從來不會連成一塊（測試照片會碎成 58 塊），取最大塊只會框到整捆的一角並把邊緣的塞頭切掉。所以先把遮罩模糊化讓各面融成一個區域，取最大的區域，再框住該區域內所有綠色像素、外加 12% 邊界。

2. **放大重算** — 把整捆從原始照片裁出來、放大到約 1000 px 再處理。手機照片整張直接算，塞頭只有 20 幾像素，會全部黏成一團。超過 2200 px 的照片會先降到 2000 px，因為實測顯示更高解析度不會改變答案，只會慢 8 倍。

3. **量單顆面積** — 對綠色遮罩做 Otsu 自動門檻把透明套環排除，切出各塊綠色區域，取面積的**中位數**當一顆的面積。

   用中位數而不是最小值：最小的那塊往往是只露出一部分的塞頭，拿它當單位會把總數算成將近兩倍（實測 36 vs 正解 20）。

4. **面積相除** — 每塊區域各自算 `四捨五入(區塊面積 / 單顆面積)`、至少算一顆，相加就是總數。黏在一起的兩顆面積約兩倍，自然被算成 2。

另外會獨立跑一次距離轉換 + 分水嶺分割（含 h-maxima 抑制）當**交叉核對**，兩個數字一致與否顯示在資訊列。頁面上的「判定明細」表列出每一塊的面積、比值與判定顆數，比值接近 .5 的會標記出來 —— 那是唯一可能算錯的地方。

## 準確度

以一張手拿 20 顆綠色塞頭的照片驗證，面積法算出 20 顆。單顆塞頭的面積非常一致（彼此只差 −7%／+5%），所以中位數當單位很可靠。

同一張照片縮成不同大小的實測：

| 照片寬度 | 塞頭約幾 px | 面積法 | 分水嶺核對 |
|---|---|---|---|
| 3312（原圖） | 146 | **20** | 19 |
| 2000 | 88 | **20** | 19 |
| 1400 | 63 | **20** | 19 |
| 1100 | 48 | **20** | 19 |
| 800 | 36 | **20** | 19 |
| 600 | 26 | **20** | 19 |
| 450 | 19 | **20** | 19 |
| 340 | 24 | 7 ✗ | 16 |

一路縮到 450 px 寬、每顆塞頭只剩 19 px 都還算對，340 px 才失效。**解析度不是瓶頸** —— 讓整捆佔滿畫面的好處在背景乾淨、對焦準、透視變形小，不在像素多。

主要誤差來源是幾何：塞頭朝向不同會讓投影面積有落差，使比值偏離整數。真的算錯時，在圖上點一下就修好了。

## 參數

進階參數區有四個滑桿，調整後會立刻重算：

| 參數 | 作用 |
|---|---|
| 單顆面積微調 | 直接乘在自動量到的單顆面積上，最直接影響總數。總數偏多就調大，偏少就調小。 |
| 最小面積 | 相對單顆面積的下限。調小會納入只露一角的塞頭，但也容易把雜訊算進來。 |
| 顏色門檻 | 綠色判定的鬆緊。調大只認最飽和的綠面（塞頭之間分得更開），調小會把淺綠的透明套環也算進來。 |
| 背景剔除 | 用「對焦清楚程度」剔除模糊背景。背景有綠色物件時調大，塞頭本身被誤刪時調小。 |

## 部署

`main` 分支一有 push，`.github/workflows/pages.yml` 就會把整個 repo 發佈到 GitHub Pages。`actions/configure-pages` 帶 `enablement: true`，第一次執行會自動開啟 Pages，不需要手動去 Settings 設定。

本機使用不需要任何工具，直接在瀏覽器開 `index.html` 即可。
