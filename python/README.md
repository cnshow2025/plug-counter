# 塞頭計數器 — Python + OpenCV + Streamlit

用筆電外接的 webcam 拍一張，數出綠色塞頭的數量。一顆塞頭 = 一根管子。

演算法與同 repo 根目錄的網頁版 (`index.html`) 相同，已用一張 20 顆塞頭的照片驗證：
**自動判定 20 顆**，單顆面積 5574 px²，耗時約 240 ms。

```
python/
  counter.py        演算法（純 OpenCV，與介面無關，可單獨使用或做批次處理）
  app.py            Streamlit 介面：相機、點圖修正、自動存檔
  requirements.txt
```

## 安裝與執行

```bat
cd D:\Projects\0_Python\3_MFG\Tube_Counter\python
pip install -r requirements.txt
streamlit run app.py
```

瀏覽器會自動開啟 http://localhost:8501。

**相機編號**：外接 webcam 通常是 `1`，筆電內建鏡頭多半是 `0`。開不起來就在側邊欄換個數字，或按「重新連線」。Windows 下程式會用 DSHOW 後端開相機 —— 預設的 MSMF 後端常常要等好幾秒。

## 怎麼用

1. 側邊欄選好相機編號與解析度，畫面會即時預覽
2. 對準塞頭，按「**拍攝並計數**」
3. 數字立刻出現，圖上每顆塞頭標一個編號
4. 算錯就**直接點圖**：點空白處補一顆、點圈圈刪一顆
5. 改了參數不用重拍，按「用目前參數重算」

沒有相機也可以直接上傳照片檔。

## 自動存檔

每次計數會寫進輸出資料夾（預設 `captures/`）：

```
captures/
  annotated/20260930_081827.jpg   標了編號的圖
  raw/20260930_081827.jpg         原始照片
  log.csv                         一次計數一列
```

`log.csv` 記錄時間、自動顆數、最終顆數、人工新增／刪除、當時的所有參數與三個核對數字。

人工修正之後按「更新紀錄（含人工修正）」會另存一筆修正後的結果。

> **原始照片 + 你的人工修正 = 訓練資料。** 如果之後要走 AI 那條路（例如白色塞頭沒辦法用顏色分辨，只能靠形狀），這些檔案就是現成的資料集，不必另外花時間標註。

## 演算法

1. **找整捆** — 縮到 600 px，用色相找出彩色區域，並用局部邊緣能量剔除模糊背景。
   這裡不能取「最大的連通區塊」：每顆塞頭都被自己的透明套環圍住，整捆從來不會連成一塊（實測會碎成 58 塊），取最大塊只會框到整捆的一角並把邊緣的塞頭切掉。改成先把遮罩模糊化讓各面融成一個區域，取最大的區域，再框住該區域內所有彩色像素、外加 12% 邊界。
2. **放大重算** — 把整捆裁出來放大到約 1000 px。手機或高解析相機的整張影像直接算，塞頭只有 20 幾 px，會全部黏成一團。超過 2000 px 的來源會先縮小，實測不影響結果。
3. **量單顆面積** — 對飽和度做 Otsu 自動門檻排除透明套環，切出各塊，取面積的**中位數**。
   不能取最小值：最小的那塊往往是只露出一部分的塞頭，拿它當單位會把總數算成將近兩倍（實測 36 vs 正解 20）。
4. **面積相除** — 每塊各自算 `四捨五入(區塊面積 / 單顆面積)`、至少一顆，相加即總數。
5. **外形檢查** — 每塊求最小外接矩形。塞頭從側面拍時**長邊幾乎不變（±1%）**，只有短邊被拉寬（±23%），所以長邊是比面積（±5%）更穩的尺。外形只容得下一顆時，即使面積偏大也判一顆。

### 兩個交叉核對

- **面積總和** — `round(所有比值的總和)`，只四捨五入一次。顯示時保留小數，越接近整數越可靠。
- **核心核對** — 距離轉換上彼此分離的核心數，完全獨立於面積法。

三個數字一致時最可靠。

> 網頁版這裡跑的是 h-maxima 抑制的分水嶺氾濫；那個作法要逐像素迴圈，在 Python 裡對 30 萬像素要好幾秒，所以改成向量化的核心計數。兩者都是獨立的第二意見，但不是同一個演算法，數字可能略有出入（測試照片上網頁版 19、Python 版 19，面積法 20）。

### 為什麼主算法用個別區塊而不是總面積相除

把單顆面積刻意調偏後的實測（正解 20 顆）：

| 單顆面積誤差 | 個別區塊 | 總面積 |
|---|---|---|
| −3% | 21 ✗ | 21 ✗ |
| −2% | **20 ✓** | 21 ✗ |
| −1% ～ +3% | 20 ✓ | 20 ✓ |
| +5% | **20 ✓** | 19 ✗ |
| +10% | **20 ✓** | 18 ✗ |

總面積法的容許誤差是 ±0.5÷總數，**塞頭越多越脆弱**（20 顆時 ±2.5%，100 顆時只剩 ±0.5%）；個別區塊法不隨數量縮小。總面積法對只露出一部分的塞頭也會低估，個別區塊法的「至少算一顆」能正確處理。

## 白色塞頭

**顏色法對白色行不通。** 白色塞頭與手指亮部同為「低飽和、高亮度」，實測會有 8 個假標記落在手指上。要數白色塞頭只能靠形狀，也就是訓練模型。

## 命令列用法

`counter.py` 可以單獨跑，方便批次驗證：

```bat
python counter.py D:\photos\*.jpg
```

或在自己的程式裡用：

```python
import cv2
from counter import count_plugs, Params

img = cv2.imread("photo.jpg")
res = count_plugs(img, Params(hue_center=168, unit_adj=1.0))
print(res.count, "顆")
for b in res.blobs:
    print(b.area, round(b.ratio, 2), b.k, b.note)
cv2.imwrite("out.jpg", res.annotate())
```

## 拍攝建議

- 讓整捆佔畫面大一點、背景單純、對焦在塞頭上
- 解析度不用擔心：實測照片縮到 450 px 寬（每顆只剩 19 px）仍然算對，340 px 才失效
- 正上方垂直拍比側拍好 —— 側拍會把短邊拉寬，讓比值偏離整數
